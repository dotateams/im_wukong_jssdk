# SDK 调整 E2EE 缓存保留、私聊文件懒解密与首次登录同步标记

## 背景

Web 端需要在退出登录后保留 E2EE 本地缓存和密钥，以提升重新登录后的历史可读性。同时，私聊 E2EE 普通文件在刷新或切换会话后必须继续支持点击下载解密，SDK 不能依赖临时 `blob:` 状态。

首次登录不拉历史主要由 Web 控制，但 SDK 应提供清晰的能力边界：缓存不因退出被清理；文件原文可根据持久化消息元数据重新懒加载；历史同步调用方可以通过外部策略决定是否跳过初始化阶段的同步。

## 目标

- SDK 不在退出登录路径中主动清理 E2EE 本地缓存或密钥。
- SDK 保留已有缓存清理能力作为显式 API，但 Web 默认退出不调用。
- SDK 私聊 E2EE 普通文件必须能根据持久化消息内容重新下载密文并解密原文。
- SDK 对普通文件保持点击后懒解密，不在消息接收、历史拉取或消息渲染阶段自动下载原文件。
- SDK 需要让 Web 能安全地区分“可跳过首次历史拉取”和“重连必须同步”的调用场景。

## 非目标

- 不改变群聊 sender key 逻辑。
- 不改变图片、GIF、自定义表情缩略图的既有处理逻辑。
- 不实现大文件长期明文缓存。
- 不直接决定 Web 是否拉历史，SDK 只提供接口和稳定行为。
