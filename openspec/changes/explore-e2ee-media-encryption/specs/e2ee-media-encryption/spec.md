# E2EE 媒体加密需求

## ADDED Requirements

### Requirement: 加密频道媒体文件本体必须端到端加密

当频道 `is_e2e=true` 时，客户端发送图片、GIF、用户私有上传表情等媒体消息前，必须在本地加密媒体文件本体，再上传密文文件。

#### Scenario: 加密频道发送图片

- **Given** 当前频道已开启 E2EE
- **And** 用户选择一张图片发送
- **When** SDK 准备发送消息
- **Then** SDK 必须先使用本地随机媒体密钥加密图片字节
- **And** 上传到服务端的文件必须是密文
- **And** WuKongIM 消息体中不得出现图片明文 URL 或明文业务载荷

#### Scenario: 普通频道发送图片

- **Given** 当前频道未开启 E2EE
- **When** 用户发送图片
- **Then** 图片发送流程必须保持现有上传和展示逻辑

### Requirement: 媒体解密密钥必须通过现有 E2EE 消息体保护

媒体文件密钥、nonce、哈希、原始类型等解密元数据必须作为 E2EE 明文载荷的一部分，再由现有单聊或群聊 E2EE 流程加密后发送。

#### Scenario: 服务端查看加密媒体消息

- **Given** 用户在 E2EE 频道发送图片
- **When** 服务端、WuKongIM 或数据库查看消息内容和文件内容
- **Then** 只能看到加密消息体和密文文件
- **And** 不能看到媒体密钥、nonce、图片明文或可直接展示的图片 URL

### Requirement: 实时消息和历史消息都必须支持媒体解密

SDK 必须在 WebSocket 实时接收和历史消息拉取两条路径上都处理 E2EE 媒体解密。

#### Scenario: 接收端实时收到加密图片

- **Given** 接收端在线
- **When** 收到加密图片消息
- **Then** SDK 必须先解密消息体得到媒体元数据
- **And** 下载密文文件并本地解密
- **And** Web UI 应展示解密后的图片

#### Scenario: 接收端刷新后查看历史加密图片

- **Given** 接收端刷新浏览器或重新登录
- **When** 拉取历史消息
- **Then** 历史加密图片必须能重新下载、解密并展示

### Requirement: GIF 和表情必须按资源类型纳入加密范围

加密频道内发送 GIF、公共自定义表情、用户私有上传表情、Lottie 表情时，必须按资源类型采用不同的 E2EE 策略。

#### Scenario: 加密频道发送 GIF

- **Given** 当前频道已开启 E2EE
- **When** 用户发送 GIF 动图
- **Then** GIF 文件本体必须加密上传
- **And** 客户端必须生成 GIF 静态首帧缩略图并加密上传
- **And** 接收端必须优先解密缩略图展示
- **And** 用户查看或播放时必须解密 GIF 原文件展示

#### Scenario: 加密频道发送公共自定义表情

- **Given** 当前频道已开启 E2EE
- **And** 表情来自公共表情库
- **When** 用户发送公共自定义表情
- **Then** 客户端不得重复上传一次性密文附件
- **And** 表情 ID、包 ID、版本、URL、名称、类型等消息元数据必须通过 E2EE 消息体保护
- **And** 普通频道公共表情发送逻辑必须保持现状

#### Scenario: 加密频道发送用户私有上传表情

- **Given** 当前频道已开启 E2EE
- **And** 表情来自用户私有上传资源
- **When** 用户发送该表情
- **Then** 客户端必须按加密媒体处理表情文件本体
- **And** 必须生成并加密上传缩略图

### Requirement: 明文历史和普通频道必须兼容

新增 E2EE 媒体能力不得破坏旧明文媒体消息。

#### Scenario: 查看旧明文图片历史

- **Given** 频道中存在上线前发送的明文图片
- **When** 用户查看历史消息
- **Then** Web 必须按原逻辑展示图片

#### Scenario: 普通频道发送自定义表情

- **Given** 当前频道未开启 E2EE
- **When** 用户发送自定义表情
- **Then** 发送格式和展示逻辑必须保持现状

### Requirement: 普通文件不纳入本次媒体 E2EE 范围

本次媒体 E2EE 只覆盖图片、GIF、自定义表情，不恢复、不新增普通文件选择入口，也不要求普通文件内容类型 `8` 在本次支持 E2EE。

#### Scenario: 用户在加密频道发送普通文件

- **Given** 当前频道已开启 E2EE
- **When** 用户尝试发送普通文件
- **Then** 客户端不应把普通文件作为本次媒体 E2EE 支持能力处理
- **And** 不得静默回退为明文普通文件发送

### Requirement: 媒体大小和压缩策略必须沿用现状

E2EE 媒体不得引入新的专属大小限制。图片压缩、GIF 保留原文件等规则应与普通频道当前行为一致。

#### Scenario: 发送普通图片

- **Given** 当前 Web 图片入口会压缩普通图片
- **When** 用户在 E2EE 频道发送图片
- **Then** 客户端必须先按现有规则得到最终待上传图片文件
- **And** 再对该最终文件做 E2EE 媒体加密

### Requirement: 解密后的媒体 Blob 不得持久化缓存

客户端不得把解密后的图片、GIF、自定义表情 Blob 持久化保存到 IndexedDB、localStorage 或 SQLite。

#### Scenario: 刷新后查看加密图片历史

- **Given** 用户刷新浏览器
- **When** 再次进入包含 E2EE 图片的会话
- **Then** SDK 必须通过历史消息重新解密媒体元数据
- **And** 按需下载密文文件并解密展示
- **And** 不依赖本地持久化的明文 Blob

### Requirement: 第一版必须生成客户端加密缩略图

第一版 E2EE 图片和 GIF 必须新增独立缩略图文件和字段。缩略图必须由客户端生成，并在本地加密后上传。

#### Scenario: 展示加密图片

- **Given** 接收端收到 E2EE 图片消息
- **When** Web 展示图片消息
- **Then** SDK 必须优先下载并解密缩略图
- **And** UI 必须先展示缩略图
- **And** 用户点击查看大图时再下载并解密原图
- **And** 不要求服务端生成缩略图

#### Scenario: 原图和缩略图密钥隔离

- **Given** 用户发送 E2EE 图片
- **When** 客户端生成原图密文和缩略图密文
- **Then** 原图和缩略图必须使用不同的随机 key 和 nonce

### Requirement: 失败必须安全关闭

加密频道内媒体加密、上传、下载、校验或解密失败时，不得自动回退为明文发送或明文展示。

#### Scenario: 媒体加密失败

- **Given** 当前频道已开启 E2EE
- **When** 图片加密失败
- **Then** 消息必须发送失败
- **And** UI 应提示用户重试
- **And** 不得发送明文图片

#### Scenario: 媒体哈希校验失败

- **Given** 接收端下载到密文文件
- **When** 密文哈希与消息体中的 `sha256` 不一致
- **Then** SDK 必须拒绝解密并标记该媒体消息加载失败

### Requirement: 日志不得泄露敏感媒体信息

调试日志可以打印媒体类型、大小、发送阶段、是否密文、解密成功失败，但不得打印密钥、nonce、明文文件内容、完整明文 URL 中的敏感参数。

#### Scenario: 开启调试日志发送加密图片

- **Given** Web E2EE 调试日志已开启
- **When** 用户发送加密图片
- **Then** 控制台可以显示“媒体已加密、密文大小、上传成功、消息已发送”
- **And** 不得显示媒体密钥、nonce 或图片明文字节

## OPEN Questions

- 后续是否扩展到普通文件、语音、短视频。
- Web 完成后 Flutter 是否采用完全相同的“不持久化明文媒体 Blob”策略。
