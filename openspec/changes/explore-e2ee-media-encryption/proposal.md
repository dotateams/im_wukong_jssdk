## 背景

现有 E2EE 已覆盖文本类普通消息，媒体消息仍沿用“先上传文件，再发送 URL 元数据”的明文链路。为了让加密频道达到生产可用的隐私预期，图片、GIF、自定义表情等媒体内容也需要端到端加密。

当前 Web 端主要通过图片入口发送图片和 GIF。代码中已有 `FileContent` 和拖拽文件展示能力，但普通文件不是本次媒体 E2EE 范围，本次只处理图片、GIF、自定义表情。

## 目标

- 加密频道内发送的图片、GIF、用户私有上传表情资源必须加密文件本体。
- 加密频道内发送公共自定义表情时，公共资源本体不重复上传为一次性密文附件，但表情消息元数据必须走 E2EE。
- 图片和 GIF 第一版必须支持客户端生成并加密上传缩略图。
- 媒体元数据中用于解密的密钥材料必须通过现有 E2EE 消息体保护，服务端和 WuKongIM 不可看到明文密钥。
- 普通频道媒体收发保持现有逻辑不变。
- 普通文件发送不纳入本次范围。
- 已存在的明文媒体历史保持可读，不做批量迁移。
- 新加密媒体历史在 Web 端拉取历史消息时必须能自动解密并展示。
- 为后续 Flutter 端实现保留跨端一致的数据结构和算法约定。

## 非目标

- 不要求服务端为 E2EE 媒体生成缩略图或在线预览，缩略图由客户端本地生成并加密上传。
- 不批量重加密历史文件。
- 不改变 WuKongIM 的底层消息投递协议。
- 不在本阶段恢复或新增普通文件发送入口。
- 不把 Web 和 Flutter 端做成共享同一份私钥；仍然保持每个设备独立密钥。

## 影响范围

- `im_wukong_jssdk`：新增媒体加密/解密、上传前加密、下载后解密、内存临时缓存、错误处理、测试。
- `TangSengDaoDaoWeb`：接入 SDK 媒体解密结果，图片/GIF/自定义表情展示 Blob URL，发送入口保持现有体验。
- `TangSengDaoDaoServer`：原则上不需要理解 E2EE 媒体内容，只继续提供上传和下载能力；如需支持大文件、CORS、Range、缓存头，再按测试结果补充。
- `WuKongIM`：不需要理解媒体明文，只保存和投递加密后的消息体。
- `im-app-flutter`：本阶段仅要求文档约定兼容，等 Web 完成后再实现。

## 已确认规则

- 普通文件不用管，本次只做图片、GIF、自定义表情。
- 文件大小和图片压缩策略沿用现状，不新增 E2EE 专属大小限制。
- 不持久化保存解密后的图片/GIF/表情 Blob，减少本地缓存占用。
- 媒体密钥和密文文件链接保留在 E2EE 消息体中，历史展示时重新解密消息体并按需下载密文文件。
- 公共自定义表情不做一次性密文附件，只加密表情 ID、包 ID、版本、URL、名称等消息元数据。
- 用户私有上传表情按加密媒体处理。
- 第一版做独立加密缩略图：图片缩略图由客户端生成，GIF 缩略图使用静态首帧。
- E2EE 媒体发送失败时不允许转为明文发送。
