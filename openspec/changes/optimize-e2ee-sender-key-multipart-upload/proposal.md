# JavaScript SDK 群 SenderKey 分片上传优化

## 背景

SDK 原先按 100 个设备循环调用完整 bundle 上传接口，但服务端会按同一 SenderKey 覆盖整包，
造成前批信封丢失。一次性完整上传解决了正确性问题，却放大了超大群的请求体和失败重传成本。

## 目标

- 小群继续一次性上传，避免额外协议往返。
- 大群使用服务端 `version=3` 分片暂存与原子提交协议。
- 默认每片 100 个设备、最多并发 3 片，均可通过 E2EE 配置调整。
- 提交成功前不发送群消息，不允许明文降级。
- 新接口明确不支持时，仅回退为一次性完整上传。
- 与 C# SDK 保持字段、边界和失败语义一致。

## 非目标

- 不改变 SenderKey 信封密文和群消息格式。
- 不把多个旧完整上传请求当作分片协议。
