# E2EE 媒体文件快速转发优化

## 背景

当前 E2EE 图片、GIF、自定义表情、视频和文件已经支持加密上传、分片上传、下载解密和本地缓存。现有转发逻辑如果对媒体文件简单“下载解密后重新上传”，会在大文件场景产生明显的 CPU、内存、网络和存储浪费；如果直接复用原消息密文，又会导致目标频道无法解密或安全边界混乱。

因此需要把 E2EE 媒体转发统一改为“密文文件复用 + mediaKey 信封重包”的模式。文件本体只用独立随机 `mediaKey` 加密一次；转发到加密频道时复用密文对象，只给目标频道重新封装 `mediaKeyEnvelope`。

## 目标

- 支持 E2EE 加密图片、GIF、自定义表情、视频和普通文件快速转发。
- 大文件、小文件、分片文件、非分片文件统一使用同一套转发方式。
- 转发到加密频道时复用原密文文件或原分片 manifest，只重新封装文件 `mediaKey`。
- 转发到普通频道时不暴露 E2EE 信封；优先按文件 MD5 查找可复用明文文件，命中则复用，未命中才本地解密后重新上传。
- 保证服务端、MinIO、WuKongIM 不接触明文文件和明文 `mediaKey`。
- 清理上传文件时，同时清理 E2EE 分片 session、分片记录、临时密文对象和无引用文件对象。
- 保持现有非媒体消息转发、回复、合并转发逻辑兼容。
- 为后续 Flutter 端复用相同协议预留结构。

## 非目标

- 不在本次需求中重写普通文本消息转发规则。
- 不做服务端明文转码、预览、查毒或内容识别。
- 不做云端解密，也不允许服务端保存明文 `mediaKey`。
- 不强制改变当前分片上传会话实现，仅在转发和清理时复用/维护已完成的密文对象和 manifest。

## 推荐方案

采用“文件本体密钥 + 频道信封”的两层结构：

1. 每个 E2EE 媒体文件生成一个独立随机 `mediaKey`。
2. 文件本体、缩略图和每个分片使用 `mediaKey` 或由 `mediaKey` 派生出的子密钥加密。
3. 消息内容中不保存明文 `mediaKey`，只保存被当前频道 E2EE 密钥封装后的 `mediaKeyEnvelope`。
4. 转发到加密频道时，发送端先解开源消息的 `mediaKeyEnvelope` 得到 `mediaKey`。
5. SDK 使用目标频道的 E2EE 密钥体系重新封装 `mediaKey`，生成新的目标频道 `mediaKeyEnvelope`。
6. 新消息复用原文件密文 URL、缩略图 URL、分片 manifest、hash、MD5、大小和文件名等元数据。

这样无论是 2MB 小文件还是 1GB 分片文件，转发到加密频道都只需要发送一条新消息，不需要重新上传文件。

## 加密频道转普通频道

加密频道转普通频道允许转发，但目标普通频道必须收到普通文件消息，不能收到 E2EE 密文文件和信封。

处理顺序：

1. SDK 解开源 `mediaKeyEnvelope`，确认当前设备有权读取文件。
2. 从源媒体元数据读取原始文件 MD5。如果旧消息没有 MD5，可用原始文件 digest；仍缺失时降级为解密后计算。
3. Web 调用服务端普通文件 MD5 查询或秒传能力。
4. 如果服务端存在同 MD5 的普通明文对象，直接复用该普通文件对象发送普通文件消息。
5. 如果不存在，客户端下载源密文文件，本地解密成明文，再按普通文件上传逻辑上传。
6. 普通频道消息只保存普通文件 URL、文件名、大小、MIME、MD5 等普通文件字段，不保存 `mediaKeyEnvelope`。

## 影响范围

- `im_wukong_jssdk`：新增 E2EE 媒体转发封装能力，支持从源消息提取 `mediaKey`、构造目标频道媒体消息、重包信封、复用 manifest。
- `TangSengDaoDaoWeb`：转发 UI 调用 SDK 新接口，处理普通频道 MD5 复用、未命中重传、错误提示。
- `TangSengDaoDaoServer`：必要时补充密文对象引用/权限校验能力、普通文件 MD5 查询能力、E2EE 分片清理能力。
- `WuKongIM`：继续只负责消息投递，不理解媒体信封内容。

## 风险

- 如果当前媒体文件密文 URL 权限绑定源频道，目标频道成员可能无法下载复用密文，需要服务端支持“密文对象引用授权”或可被消息授权的下载鉴权。
- 如果源消息缺少可解开的 `mediaKeyEnvelope`，无法快速转发，只能提示不可转发或降级为重新下载解密上传。
- 加密频道转普通频道会产生明文文件外发，需要确认业务上允许该行为。
- 同一文件并发转发到多个频道时，若服务端引用创建非幂等，可能出现重复引用或引用计数错误。
- 清理任务如果没有引用计数或对象引用表，可能误删被转发消息仍在使用的密文对象；加密转普通中途失败的临时明文对象若不清理会产生孤儿对象。
